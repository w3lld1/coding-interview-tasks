# Ограничитель запросов «ведро с жетонами»

**Сложность:** средняя · **Языки:** Python, JavaScript, TypeScript · **Темы:** [Асинхронность и потоки](../async/), [Математика](../math/)

**[▶ Решить онлайн на CodeShare](https://code-share.ru/practice/CS-225?utm_source=github&utm_medium=tasks-repo)**

Запросы приходят в моменты `requests` (миллисекунды от вызова, список не убывает), запросу `i` нужно `costs[i]` жетонов (`1 ≤ costs[i] ≤ capacity`). Жетоны лежат в ведре вместимостью `capacity`; в момент 0 оно полное. В каждый момент, кратный `refill` (`refill`, `2·refill`, …), в ведро добавляется один жетон, а если ведро уже полное, этот жетон пропадает.

Запросы обслуживаются строго по очереди в порядке списка: запрос обслуживается в первый момент, когда он уже пришёл, все запросы перед ним обслужены и в ведре не меньше `costs[i]` жетонов; тогда из ведра забирают `costs[i]` жетонов. Запрос не может обогнать ожидающий запрос перед собой, даже если ему жетонов хватило бы. В один момент сначала добавляется жетон (если момент кратен `refill`), потом приходят запросы этого момента, потом обслуживаются все, кому хватает жетонов, по очереди.

Верните для каждого запроса момент его обслуживания, в порядке списка; для пустого списка — `[]`. Функция асинхронная: можно моделировать ожидание таймерами, но ответ — это только список моментов. Запросов до 1000, моменты до 10^6, `1 ≤ capacity ≤ 100`, `1 ≤ refill ≤ 10^5`; моменты ответа могут быть намного больше 10^6. Перебор по каждой миллисекунде слишком медленный. Текущее время в миллисекундах: `Date.now()` в JS/TS, `round(asyncio.get_running_loop().time() * 1000)` в Python.

Пример: `[0, 0, 0, 5]`, `[1, 1, 1, 1]`, `capacity = 2`, `refill = 10` → `[0, 0, 10, 20]`.
