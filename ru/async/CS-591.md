# Ограничитель «скользящее окно»

**Сложность:** средняя · **Языки:** Python, JavaScript, TypeScript · **Темы:** [Асинхронность и потоки](../async/), [Математика](../math/)

**[▶ Решить онлайн на CodeShare](https://code-share.ru/practice/CS-591?utm_source=github&utm_medium=tasks-repo)**

Даны список заданий `jobs` и числа `gap ≥ 0`, `limit ≥ 1`, `window ≥ 1` (миллисекунды). Задание — асинхронная функция без аргументов: вызовите её (`await job()`), чтобы выполнить; она может завершиться ошибкой (исключением). Запрос `i` приходит в момент `i · gap` мс после вызова вашей функции и просит запустить задание `i`.

Ограничитель принимает запрос, если среди уже принятых запросов меньше `limit` таких, что момент их прихода `s` удовлетворяет `t − window < s ≤ t`, где `t` — момент нового запроса. Принятый запрос запускает задание сразу, и задания работают одновременно, без ограничения числа. Отклонённый запрос отбрасывается: его задание не вызывается и больше в расчётах не участвует. Принятый запрос учитывается в окне, даже если его задание потом завершилось ошибкой.

Верните значения успешно завершившихся принятых заданий в порядке завершения; при равных моментах идут по возрастанию индекса. Для пустого списка верните `[]`. Текущее время в миллисекундах: `Date.now()` в JS/TS, `round(asyncio.get_running_loop().time() * 1000)` в Python. До 50 заданий.

Пример: `gap = 10`, `limit = 2`, `window = 25`, четыре задания по 5 мс возвращают `1`, `2`, `3`, `4` → `[1, 2, 4]` (запрос в 20 мс отклонён: в окне (−5, 20] уже два принятых, а в 30 мс окно (5, 30] содержит только запросы в 10 и 20, из которых принят один).
