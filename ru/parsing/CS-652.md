# Конфигурация INI со ссылками между значениями

**Сложность:** сложная · **Языки:** любой из Python, JavaScript, TypeScript, Java, Go · **Темы:** [Разбор и проверка данных](../parsing/), [Исключения](../errors/), [Рекурсия и перебор](../recursion/)

Файл настроек дан списком строк `lines`. Верните значения ключей из списка `queries` (каждый запрос — `секция.ключ`) после подстановки ссылок, в порядке запросов.

Каждая строка сначала очищается от пробелов по краям, затем:
- пустая строка и строка, начинающаяся с `;` или `#`, пропускаются;
- `[имя]` начинает секцию; имя — непустое, из латинских букв, цифр и `_`, без пробелов внутри скобок; секция может встречаться несколько раз, её ключи объединяются;
- `ключ = значение` — ключ текущей секции: ключ — текст до первого `=` без крайних пробелов (имя по тем же правилам), значение — текст после него без крайних пробелов (может быть пустым и содержать `=`);
- любая другая строка — ошибка; ключ до первой секции и повтор ключа в одной секции — тоже ошибки.

В значении `${ключ}` — ссылка на ключ той же секции, `${секция.ключ}` — на ключ другой секции; ссылка заменяется итоговым значением того ключа (его ссылки раскрываются в его секции). `$$` означает один символ `$`; любой другой `$` (без `{` или `$` после него, без закрывающей `}`, с неверным именем внутри) — ошибка.

Проверяется весь файл: все значения должны раскрываться, даже если их не запрашивают. Сообщите об ошибке: бросьте исключение, в Go верните error, при любой ошибке формата, ссылке на несуществующий ключ, цикле ссылок и запросе несуществующего ключа.

Пример: `["[app]", "name = Shop", "title = ${name}!"]`, `["app.title"]` → `["Shop!"]`.
