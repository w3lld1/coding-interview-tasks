# Значение по пути в JSON с проверкой документа

**Сложность:** сложная · **Языки:** любой из Python, JavaScript, TypeScript, Java, Go · **Темы:** [Разбор и проверка данных](../parsing/), [Исключения](../errors/), [Рекурсия и перебор](../recursion/)

Дан текст `document` в упрощённом JSON и путь `path`. Проверьте документ и верните значение по пути, записанное компактно.

Документ — одно значение; вокруг и между лексемами допустимы пробелы, переводы строк и табуляции:
- объект `{"ключ": значение, ...}` (может быть пустым), ключи — строки, повторять ключ в одном объекте нельзя;
- массив `[значение, ...]` (может быть пустым); запятая после последнего элемента — ошибка;
- строка в двойных кавычках; внутри — любые символы, кроме перевода строки и табуляции, а `"` и `\` пишутся только экранированными; допустимы ровно четыре экранирования: `\"`, `\\`, `\n`, `\t`;
- целое число: необязательный `-` и цифры без ведущих нулей (`0`, `-15`; `012` — ошибка);
- `true`, `false`, `null`.

Путь: пустая строка означает весь документ; иначе это шаги без пробелов — имя ключа из латинских букв, цифр и `_` (первый шаг пишется без точки, следующие через `.`) или индекс массива `[n]` (`n` — цифры без ведущих нулей, отсчёт с `0`), например `shop.items[1].qty`. Шаг-имя применяется только к объекту, шаг-индекс — только к массиву.

Результат — значение без пробелов: ключи в исходном порядке, пары `"ключ":значение` через запятую, числа как в документе, строки заново экранированы четырьмя способами выше.

Сообщите об ошибке: бросьте исключение, в Go верните error, если документ некорректен (в том числе лишний текст после значения или повтор ключа, даже вне пути), путь записан неверно или по пути нет значения.

Пример: `"{\"a\": [1, {\"b\": null}]}"`, `"a[1]"` → `"{\"b\":null}"`.
