# Контейнер сервисов со временем жизни

**Сложность:** средняя · **Языки:** любой из Python, JavaScript, TypeScript, Java, Go · **Темы:** [Функции и замыкания](../functions/), [Исключения](../errors/), [Деревья и графы](../trees-graphs/)

**[▶ Решить онлайн на CodeShare](https://code-share.ru/practice/CS-659?utm_source=github&utm_medium=tasks-repo)**

Контейнер внедрения зависимостей описан списком `services`. Каждая строка — это `имя время_жизни зав1 зав2 …`: имя сервиса, его время жизни (`singleton`, `scoped` или `transient`) и имена сервисов, которые нужны его фабрике (может не быть ни одного). Слова разделены одним пробелом, имена различны.

Запросы `queries` выполняются по очереди, каждый запрос — это получение одного сервиса. Чтобы получить сервис, контейнер сначала получает все его зависимости в указанном порядке, затем один раз вызывает фабрику самого сервиса. Время жизни решает, когда фабрика вызывается снова:
- `singleton` — экземпляр создаётся один раз на весь вызов функции и потом переиспользуется во всех запросах;
- `scoped` — один экземпляр на запрос: внутри одного запроса переиспользуется, в следующем запросе создаётся заново;
- `transient` — новый экземпляр при каждом обращении.
Переиспользованный экземпляр не трогает свои зависимости.

Верните для каждого запроса, сколько раз за него были вызваны фабрики. Сообщите об ошибке (бросьте исключение, в Go верните error), если при получении встретилось имя, которого нет в `services`; если сервис понадобился, пока он сам ещё строится (цикл); или если сервис `scoped` понадобился (даже уже созданный), пока строится какой-нибудь `singleton`. Ошибка относится ко всему вызову. Сервисы, до которых запросы не дошли, не проверяются. До 10 сервисов.

Пример: `["db singleton", "repo transient db", "api scoped repo repo"]`, `["api", "api", "repo"]` → `[4, 3, 1]`.
