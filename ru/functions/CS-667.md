# Рекурсия через LRU-кэш ограниченного размера

**Сложность:** средняя · **Языки:** любой из Python, JavaScript, TypeScript, Java, Go · **Темы:** [Функции и замыкания](../functions/), [Рекурсия и перебор](../recursion/), [Словари и множества](../hashing/)

Функция `f` задана рекурсивно одним из правил `name`; все вычитания и деления дают аргументы ≥ 0:
- `fib`: `f(n) = n` при `n < 2`, иначе `f(n-1) + f(n-2)`;
- `pairs`: `f(n) = 1` при `n < 2`, иначе `f(n-2) + f(n-1)`;
- `trib`: `f(n) = 1` при `n < 3`, иначе `f(n-1) + f(n-2) + f(n-3)`;
- `split`: `f(n) = 1` при `n ≤ 1`, иначе `f(n/2) + f(n/3) + f(n/4)` (деление с округлением вниз);
- `hof`: `f(n) = 1` при `n ≤ 2`, иначе сначала `a = f(n-1)`, затем `b = f(n-2)`, и `f(n-a) + f(n-b)`.
Вызовы в правой части выполняются строго слева направо, сумма берётся по модулю `1 000 000 007`.

Каждый вызов `f`, включая самый первый и базовые случаи, идёт через кэш на `capacity` значений с вытеснением давно не использованного (LRU). Если `n` есть в кэше, результат берётся оттуда, а запись становится самой свежей. Иначе тело функции вычисляется (это «вычисление»), затем результат кладётся в кэш как самый свежий, и если записей стало больше `capacity`, удаляется самая давняя. При `capacity = 0` кэш ничего не хранит. Кэш общий для всех запросов.

Для каждого `n` из `queries` по очереди верните `[f(n), вычисления]`, где «вычисления» — сколько раз за этот запрос вычислялось тело. До 20 запросов, `0 ≤ capacity ≤ 100`, `n ≤ 10⁶`, глубина рекурсии не больше 200, а число вычислений за все запросы — не больше 200 000.

Пример: `"fib"`, `3`, `[10, 12]` → `[[55, 11], [144, 2]]`.
