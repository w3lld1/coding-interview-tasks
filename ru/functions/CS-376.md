# Вызовы рекурсии с мемоизацией и без

Число разбиений `n` на слагаемые не больше `k` считает рекурсивная функция `p(n, k)`:
- если `n = 0`, ответ `1` (рекурсии нет);
- иначе если `k = 0`, ответ `0` (рекурсии нет);
- иначе `p(n, k) = p(n, k - 1)` плюс, только если `n ≥ k`, ещё `p(n - k, k)`.

Дан список запросов `queries`, каждый — пара `[n, k]` с `0 ≤ n ≤ 40`, `0 ≤ k ≤ 40`. Для каждого запроса верните три числа `[p(n, k), plain, memo]`:
- `plain` — сколько раз была бы вызвана `p` в обычной рекурсии без запоминания, считая сам верхний вызов и вызовы с базовым ответом;
- `memo` — сколько различных пар `(n, k)` вычисляется, если результаты запоминаются (кэш в начале каждого запроса пуст): тело функции выполняется один раз на пару.

Запросы независимы друг от друга. Простая рекурсия слишком медленна для больших `n`, поэтому `plain` нужно посчитать, не выполняя её.

Пример: `[[4, 2]]` → `[[3, 17, 12]]`: три разбиения (2+2, 2+1+1, 1+1+1+1), простая рекурсия делает 17 вызовов, а с запоминанием вычисляется 12 различных пар.
