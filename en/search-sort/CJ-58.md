# Chests and keys

**Difficulty:** hard · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Searching and sorting](../search-sort/), [Trees and graphs](../trees-graphs/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CJ-58?utm_source=github&utm_medium=tasks-repo)**

You face `N` locked chests. A chest opens with a key of one specific type, and the key is used up. A chest may contain keys (possibly several of one type) that you can use later; you may hold any number of keys.

`start_keys` lists the types of the keys you hold at the start (at least one). `chests[i]` describes chest number `i + 1`: `chests[i][0]` is the type of key that opens it, the remaining numbers are the types of the keys inside. Types are numbers from 1 to 200. Return the order in which to open all the chests, as a list of chest numbers (from 1). If several orders work, return the lexicographically smallest: the first number as small as possible, then the second, and so on. If the chests cannot all be opened, return an empty list `[]`. There are up to 200 chests and up to 400 keys in total.

Example: `[1]`, `[[1], [1, 1, 3], [2], [3, 2]]` → `[2, 1, 4, 3]`.
