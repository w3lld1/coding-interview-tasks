# Value at a JSON path with document validation

**Difficulty:** hard · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Parsing and validation](../parsing/), [Errors and exceptions](../errors/), [Recursion and backtracking](../recursion/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-650?utm_source=github&utm_medium=tasks-repo)**

You get a text `document` in a JSON subset and a path `path`. Validate the document and return the value at the path in compact form.

The document is one value; spaces, line breaks and tabs are allowed around and between tokens:
- an object `{"key": value, ...}` (may be empty) with string keys; a key may not repeat within one object;
- an array `[value, ...]` (may be empty); a comma after the last element is an error;
- a string in double quotes; it may contain any character except a line break and a tab, and `"` and `\` appear only escaped; exactly four escapes are allowed: `\"`, `\\`, `\n`, `\t`;
- an integer: an optional `-` and digits without leading zeros (`0`, `-15`; `012` is an error);
- `true`, `false`, `null`.

The path: an empty string means the whole document; otherwise it is a list of steps without spaces: a key name of Latin letters, digits and `_` (the first step has no dot, later ones are joined with `.`) or an array index `[n]` (`n` is digits without leading zeros, counting from `0`), for example `shop.items[1].qty`. A name step applies only to an object, an index step only to an array.

The result is the value without spaces: keys in their original order, `"key":value` pairs joined with commas, numbers as written in the document, strings escaped again in the four ways above.

Report an error: throw an exception, or return an error in Go, if the document is malformed (including extra text after the value or a repeated key, even off the path), the path is malformed, or there is no value at the path.

Example: `"{\"a\": [1, {\"b\": null}]}"`, `"a[1]"` → `"{\"b\":null}"`.
