# Key-value store with nested transactions

**Difficulty:** hard · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Classes and OOP](../oop/), [Hash maps and sets](../hashing/), [Errors and exceptions](../errors/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-624?utm_source=github&utm_medium=tasks-repo)**

Implement a key-value store with nested transactions, empty at first and with no open transactions. Keys and values are integers, values are ≥ 0. You get a list of operations `operations` and a list of their arguments `values` (`values[i]` belongs to `operations[i]`). Return a list of results, one per operation.

Operations:
- `"set"` with arguments `key`, `value`: store the value. Result `0`.
- `"unset"` with argument `key`: delete the key (nothing happens if it is missing). Result `0`.
- `"get"` with argument `key`: the key's value, or `-1` if there is no such key.
- `"count"` with argument `value`: how many keys have this value now.
- `"begin"`: open a new transaction inside the current one. Result: the number of open transactions.
- `"rollback"`: undo every change made since the innermost transaction was opened and close it. Result: the number of open transactions.
- `"commit"`: close the innermost transaction keeping its changes. If an outer transaction is open, these changes become part of it: its `rollback` undoes them too. Result: the number of open transactions.
- `"dirty"`: how many keys now differ from what they were when the innermost transaction was opened (another value, appeared or disappeared). A key that was changed and then set back to its earlier value does not count.

If `rollback`, `commit` or `dirty` is called with no open transaction, report an error: throw an exception, or return an error in Go. The error applies to the whole call: the first bad operation aborts it. Up to 2000 operations.

Example: `["set", "begin", "set", "get", "rollback", "get"]`, `[[1, 10], [], [1, 20], [1], [], [1]]` → `[0, 1, 0, 20, 0, 10]`.
