# Call-stack profiler

**Difficulty:** easy · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Classes and OOP](../oop/), [Stacks, queues, linked lists](../stacks-lists/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-251?utm_source=github&utm_medium=tasks-repo)**

A profiler watches a program's call stack; functions are positive numbers, and one function may appear in the stack several times (recursion). At first the stack is empty. Implement the operations:
- `enter` (function): a call, the function goes onto the top; the result is the stack depth;
- `exit`: return from the innermost function; the result is its number, or `-1` for an empty stack;
- `depth`: the result is the current depth;
- `deepest`: the result is the greatest stack depth since the very start (it does not decrease on `exit`);
- `inside` (function): the result is `1` if the function is in the stack at least once right now, otherwise `0`.

Return the list of results, one per operation. `values[i]` holds the arguments of operation `i`.

Example: `["enter", "enter", "enter", "deepest", "inside", "exit", "exit", "depth", "deepest", "inside"]`, `[[1], [2], [2], [], [1], [], [], [], [], [2]]` → `[1, 2, 3, 3, 1, 2, 2, 1, 3, 0]`.
