# Cache with time to live and capacity

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Classes and OOP](../oop/), [Hash maps and sets](../hashing/), [Searching and sorting](../search-sort/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-628?utm_source=github&utm_medium=tasks-repo)**

Implement a cache of `capacity` entries (`capacity` ≥ 1), empty at first. Keys are integers and values are integers ≥ 0. You get a list of operations `operations` and a list of their arguments `values` (`values[i]` belongs to `operations[i]`). The first argument of every operation is the current time `now`; it never decreases from one operation to the next. Return a list of results, one per operation.

An entry stored at time `t` with time to live `ttl` lives while `now` < `t + ttl`; at the start of every operation all entries with `t + ttl` ≤ `now` disappear. A use of an entry is a `put` or a successful `get`; of two uses, the later one is the one further down the list.

Operations:
- `"put"` with arguments `now`, `key`, `value`, `ttl` (`ttl` ≥ 1): store the entry. If the key is already there, its value and expiry are replaced. If the key is not there and there are already `capacity` live entries, first the entry that expires soonest is evicted; among equal expiries, the one unused for the longest time. Result: the evicted key, or `-1` if nobody was evicted (disappearing by expiry is not an eviction).
- `"get"` with arguments `now`, `key`: the value of the live entry, or `-1`. The entry's expiry does not change.
- `"size"` with argument `now`: the number of live entries.
- `"ttl"` with arguments `now`, `key`: how long the entry has left to live (`t + ttl − now`), or `-1` if there is no such entry.

Up to 2000 operations.

Example: `2`, `["put", "put", "get", "put", "get"]`, `[[0, 1, 10, 5], [0, 2, 20, 5], [1, 1], [2, 3, 30, 9], [2, 1]]` → `[-1, -1, 10, 2, 10]`.
