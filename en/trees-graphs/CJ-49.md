# Arithmetic in a square

**Difficulty:** hard · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Trees and graphs](../trees-graphs/), [Strings](../strings/), [Matrices and grids](../matrices/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CJ-49?utm_source=github&utm_medium=tasks-repo)**

You get a square `grid` with side `W` (a list of `W` strings of `W` characters). Each cell holds a digit `0`–`9`, a `+` or a `-` sign, and no two digits and no two signs are horizontal or vertical neighbours.

An expression is built like this: start at any digit cell and step to a horizontal or vertical neighbour, ending on a digit again. The characters along the way form an expression `digit sign digit sign … digit`, evaluated left to right. Cells can be visited any number of times, including stepping straight back.

For each number in `queries`, find an expression with that value: the shortest one, and among the shortest the lexicographically smallest (characters compare by code, so `+` is less than `-` and signs are less than digits). Return the answers in the order of the queries.

Limits: `2 ≤ W ≤ 8`, `1 ≤ queries[i] ≤ 100`, up to 30 queries. Every query is guaranteed reachable, and the required answer's value after each number (the running total) stays within `−1000…1000`.

Example: `["2+1", "+4+", "5+1"]`, `[2, 20]` → `["2", "5+5+5+5"]`.
