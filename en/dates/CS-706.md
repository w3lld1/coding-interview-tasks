# Non-overlapping booking series for a device

**Difficulty:** hard · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Dates and time](../dates/), [Classes and OOP](../oop/), [Math](../math/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-706?utm_source=github&utm_medium=tasks-repo)**

A shared lab device is booked by repeating series. A series runs on the days `start`, `start + period`, `start + 2·period`, … up to the date `until` inclusive (an empty string means no end, that is up to `9999-12-31`) and on each such day takes the time window `[from, to)`. Windows `[a, b)` and `[c, d)` overlap if `a < d` and `c < b`. You get a list of operations `operations` and a list of their arguments `values` (`values[i]` belongs to `operations[i]`; all arguments are strings). Return a list of results, one per operation. At first there are no series.

- `"add"` `[id, start, period, from, to, until]`: if there is a day on which both the new series and a stored one run (the day is not cancelled in it) and their windows overlap, the series is not stored and the result is `"conflict <id> <date>"` for the earliest such day (on equal days, the series with the smaller `id` in lexicographic order). Otherwise the series is stored and the result is `"ok"`.
- `"cancel"` `[id, date]`: if `date` is a non-cancelled day of the series, cancel it, result `"ok"`, otherwise `"none"`.
- `"next"` `[id, date]`: the first non-cancelled day of the series not before `date`, or `"none"`.
- `"remove"` `[id]`: remove the series, result `"ok"`.

The calendar is Gregorian. A date is `YYYY-MM-DD` with a year from 2000 to 9999, a time is `HH:MM` from `00:00` to `23:59`, and `period` is one to four digits, a number from 1 to 1000. Dates in the results use the same format.

Report an error (throw an exception, or return an error in Go) for the whole call if an operation is unknown or has the wrong number of arguments, a date or time does not follow its format or the date does not exist, `period` is invalid, `from` is not earlier than `to`, `until` is earlier than `start`, the `id` of `add` is already among the stored series, or the `id` of another operation is not among them.

Example: `["add", "add", "add"]`, `[["yoga", "2024-03-04", "7", "18:00", "19:30", ""], ["ball", "2024-03-01", "3", "20:00", "21:00", "2024-12-31"], ["ball2", "2024-03-01", "3", "19:00", "20:00", ""]]` → `["ok", "ok", "conflict yoga 2024-03-04"]`.
