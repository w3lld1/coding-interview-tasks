# Project plan in working days

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Dates and time](../dates/), [Trees and graphs](../trees-graphs/), [Errors and exceptions](../errors/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-638?utm_source=github&utm_medium=tasks-repo)**

A project starts on day `start` (`"YYYY-MM-DD"`). The tasks `tasks` are strings `"name:days:dep1,dep2"`: a name of Latin letters and digits, a length of 1 to 999 working days (one to three digits), and a comma-separated list of the tasks that must finish first (it may be empty after the second colon). Working days are Monday to Friday, except the dates in `holidays` (`"YYYY-MM-DD"`).

A task without dependencies starts on the first working day not earlier than `start`; a task with dependencies starts on the first working day after the last of them finishes. A task takes `days` consecutive working days, counting its start day, and finishes on the last of them. Return strings `"name YYYY-MM-DD YYYY-MM-DD"` (start and finish) in the order of `tasks`; an empty list gives `[]`. The calendar is Gregorian; `start` and the holidays are valid.

Report an error (throw an exception, or return an error in Go) if a task string is not in this format (an empty dependency name included), a length is below 1, a name repeats, a dependency names a missing task, or the dependencies form a cycle (a task depending on itself included).

Example: `"2024-03-07"`, `["design:3:", "build:4:design", "docs:2:design", "release:1:build,docs"]`, `["2024-03-13"]` → `["design 2024-03-07 2024-03-11", "build 2024-03-12 2024-03-18", "docs 2024-03-12 2024-03-14", "release 2024-03-19 2024-03-19"]`.
