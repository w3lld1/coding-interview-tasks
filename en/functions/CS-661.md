# Parser combinators for a grammar

**Difficulty:** hard · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Parsing and validation](../parsing/), [Recursion and backtracking](../recursion/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-661?utm_source=github&utm_medium=tasks-repo)**

A grammar is a list of rules `rules`, each made of words `NAME = KIND ARG…`. Every rule is a parser: given a string and a position it either parses a piece from that position and returns the position after it, or fails. Kinds:
- `lit T`: exactly the text `T` (non-empty, no spaces);
- `char C`: one character contained in the string `C`;
- `seq R1 R2 …`: the rules in turn, each from where the previous one ended; any failure fails the whole;
- `alt R1 R2 …`: ordered choice: the result of the first rule that succeeds; after a success the other options are never tried, even if parsing fails later;
- `many R`: `R` zero or more times, greedily, while `R` succeeds and moves forward; always succeeds;
- `opt R`: `R`, or on its failure a success that does not move;
- `not R`: a success that does not move if `R` fails, otherwise a failure;
- `sep R S`: one or more `R` separated by `S`: after the first `R` it repeats the pair "`S`, then `R`" while the pair succeeds and moves forward; a failed pair consumes nothing.
The arguments of the kinds `seq`…`sep` are rule names (a rule may refer to rules declared later and to itself, but there is no left recursion).

For each string in `inputs` parse it with the rule `start` from position `0` and return the length of the parsed beginning of the string, or `-1` on failure. The whole string need not be parsed. Up to 30 rules, strings up to 50 characters.

Example: rules `["s = sep a b", "a = lit x", "b = lit -"]`, `"s"`, `["x-x-", "-x"]` → `[3, -1]`.
