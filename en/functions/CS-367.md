# Memoisation with entry time-to-live

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Hash maps and sets](../hashing/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-367?utm_source=github&utm_medium=tasks-repo)**

A function is memoised with a time-to-live (TTL) cache. For each key the cache stores a moment `s`: when the value was computed (mode `"fixed"`) or when it was last used (mode `"sliding"`). The cache starts empty.

You get `ttl` (an integer > 0), the mode `mode` and a list of calls `calls`: each call is a pair `[time, key]`, times never decrease. A call at moment `t` with key `k`:
- if `k` is not in the cache — `"miss"`: the value is computed and stored with moment `t`;
- if `k` is present and `t - s < ttl` — `"hit"`: the value comes from the cache; in `"sliding"` mode the moment `s` becomes `t`, in `"fixed"` mode it stays;
- if `k` is present but `t - s ≥ ttl` — `"expired"`: the entry is stale, the value is computed again and stored with moment `t`.

Return a list of answers, one per call.

Example: `10`, `"fixed"`, `[[0, 1], [5, 1], [10, 1], [11, 1]]` → `["miss", "hit", "expired", "hit"]`: at 10 the entry created at 0 is stale, and the new one created at 10 is alive at 11.
