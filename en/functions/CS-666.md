# Middleware chain with retries

**Difficulty:** hard · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Recursion and backtracking](../recursion/), [Stacks, queues, linked lists](../stacks-lists/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-666?utm_source=github&utm_medium=tasks-repo)**

A request (an integer) passes through a chain of middlewares `middlewares` (the first is the outermost) to a final handler. Each middleware gets the request and a function `next`, the rest of the chain, and decides itself whether to call it, how many times and with which request. A call's result is a number or a failure.

The final handler `h` numbers its calls over the whole run starting from `1`. A call whose number is in `fail_calls`, or with a negative request `x`, fails and logs `h(x)!`; otherwise the result is `2x` and it logs `h(x)=2x`.

Middlewares (parameters after `:`):
- `log:N`: logs `N>`, calls `next(x)`, then logs `<N` on success or `<N!` on failure;
- `retry:K`: calls `next(x)` and on failure repeats up to `K` more times; the result is the first success or the last failure;
- `fallback:V`: calls `next(x)`; replaces a failure with the success `V`;
- `cache`: if this middleware already stored a successful result for request `x`, returns it without calling `next`; otherwise calls `next(x)` and stores a success (failures are not stored). Each `cache` has its own memory that lives for the whole function call;
- `guard:T`: for `x < T` fails at once without calling `next`, otherwise `next(x)`;
- `add:K`: calls `next(x + K)`;
- `breaker:F:C`: a circuit breaker: while open, it decreases its block counter and fails at once; otherwise it calls `next(x)`; after `F` failed calls of `next` in a row (a success resets the count) it opens for the next `C` calls and the failure count resets.

The requests `requests` are handled in turn, and state (the numbering of `h` calls, caches, breakers) carries over between them. For each request return a string: that request's log entries separated by spaces, then `=>` and the result (a number or `fail`). If the log is empty the string starts with `=>`. Up to 10 middlewares, up to 20 requests, numbers up to 10⁶ in absolute value.

Example: `["log:A", "retry:2", "log:B"]`, `[1, 2]`, `[3]` → `["A> B> h(3)! <B! B> h(3)! <B! B> h(3)=6 <B <A => 6"]`.
