# Recursion calls with and without memoisation

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Dynamic programming](../dp/), [Recursion and backtracking](../recursion/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-376?utm_source=github&utm_medium=tasks-repo)**

The number of partitions of `n` into parts not larger than `k` is computed by the recursive function `p(n, k)`:
- if `n = 0`, the answer is `1` (no recursion);
- otherwise if `k = 0`, the answer is `0` (no recursion);
- otherwise `p(n, k) = p(n, k - 1)` plus, only if `n ≥ k`, also `p(n - k, k)`.

You get a list of queries `queries`, each a pair `[n, k]` with `0 ≤ n ≤ 40`, `0 ≤ k ≤ 40`. For each query return three numbers `[p(n, k), plain, memo]`:
- `plain` — how many times `p` would be called in plain recursion without remembering, counting the top call itself and the calls that return a base answer;
- `memo` — how many distinct pairs `(n, k)` are evaluated if results are remembered (the cache is empty at the start of each query): the body runs once per pair.

Queries are independent. Plain recursion is too slow for large `n`, so `plain` must be computed without running it.

Example: `[[4, 2]]` → `[[3, 17, 12]]`: three partitions (2+2, 2+1+1, 1+1+1+1), plain recursion makes 17 calls, and with memoisation 12 distinct pairs are evaluated.
