# Event loop: timers, microtasks and promises

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Stacks, queues, linked lists](../stacks-lists/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-721?utm_source=github&utm_medium=tasks-repo)**

Model a JavaScript-style event loop on a virtual clock (time in ms, all actions are instant). You are given a list `callbacks` of strings `"name: action; action; …"` (a body may be empty) and a number `until`. First, at moment `0`, the callback `main` runs. Return the log: strings `"TEXT@t"` in the order they were written.

Actions:
- `log TEXT` writes `"TEXT@t"`, where `t` is the current moment;
- `timeout CB MS` schedules `CB` at moment `t + MS` (`MS ≥ 0`); `interval CB MS` runs `CB` at `t + MS`, `t + 2·MS`, … (`MS ≥ 1`). Each timer gets a number `1, 2, 3, …` in order of creation (one count for both kinds);
- `clear ID` cancels timer `ID` if it has already been created (an interval no longer runs, even when cancelled from its own callback); otherwise it does nothing;
- `micro CB` puts `CB` in the microtask queue;
- `call CB` runs `CB` at once (nested), then the current callback continues;
- `promise P MS` creates a promise `P` that is fulfilled at moment `t + MS`;
- `then P CB` or `then P CB Q`: if `P` is already fulfilled, queue the microtask `CB` at once; otherwise keep it (in the order of the `then` calls) until `P` is fulfilled. With `Q`, a new promise `Q` is created, fulfilled right after this microtask `CB` has run.

Order. Timers and promise fulfilments are macrotasks; take the one with the smallest moment, on a tie the one scheduled earlier (an interval's next run is scheduled again after its callback). Fulfilling a promise puts all its waiting microtasks at the end of the queue. After `main` and after each macrotask, run the microtasks in order, including those added meanwhile, until the queue is empty. The loop stops when no macrotask with a moment of at most `until` is left.

Promise names are created only in `main`, each once; the program terminates (at most `10^4` callbacks run), up to 30 callbacks.

Example: `["main: log a; timeout t 0; micro m; log b", "t: log T", "m: log M"]`, `until = 10` → `["a@0", "b@0", "M@0", "T@0"]`.
