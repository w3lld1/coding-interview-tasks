# Glitch-free reactive signals

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Classes and OOP](../oop/), [Trees and graphs](../trees-graphs/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-716?utm_source=github&utm_medium=tasks-repo)**

Implement a graph of reactive values. You get a list of commands `operations` (words separated by one space); return a list of results, one per command.

- `signal NAME V` creates a source signal with value `V`; result `""`.
- `computed NAME F A [B]` creates a computed value: the function `F` of the values of `A` and `B` (signals or computed values created earlier); it is computed at once. Two-argument functions: `add` (sum), `sub` (`A − B`), `mul`, `max`, `min`; one-argument: `neg` (minus), `abs`, `sign` (−1, 0 or 1). Result `""`.
- `effect NAME DEP` creates an effect watching `DEP`; it fires once at once; result `"NAME=value"`.
- `set NAME V` gives a source signal a new value. Outside a batch the result is an update report (below); inside a batch the value is only remembered, result `""`.
- `batch` starts a batch (batches are not nested; inside one there are only `set` and `get`); result `""`. `commit` ends the batch and runs one update; the result is a report.
- `get NAME` is the current value as a string. Inside a batch, for a source signal it is the remembered new value, for a computed value its value before the batch.

An update. The source signals that changed are those whose value became different (in a batch, the value before the batch is compared with the last one set). A computed value is recomputed only if at least one of its direct arguments changed, and at most once per update: all its arguments must settle first. If after recomputing the value is the same, it does not count as changed (the change stops there). When everything has settled, the effects whose `DEP` changed fire, in the order the effects were created. The report is `"k|e1=v1,e2=v2"`, where `k` is how many times functions were called, followed by the effects with their new values (`"0|"` if nothing happened).

The commands are valid, up to 100 commands, all values fit in a 32-bit integer.

Example: `["signal a 1", "computed b add a a", "computed c mul a a", "computed d sub b c", "effect e d", "set a 2"]` → `["", "", "", "", "e=1", "3|e=0"]` (`d` is recomputed once, after `b` and `c`).
