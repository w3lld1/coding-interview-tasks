# Recursion through a bounded LRU cache

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Recursion and backtracking](../recursion/), [Hash maps and sets](../hashing/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-667?utm_source=github&utm_medium=tasks-repo)**

A function `f` is defined recursively by one of the rules `name`; all subtractions and divisions give arguments ≥ 0:
- `fib`: `f(n) = n` for `n < 2`, otherwise `f(n-1) + f(n-2)`;
- `pairs`: `f(n) = 1` for `n < 2`, otherwise `f(n-2) + f(n-1)`;
- `trib`: `f(n) = 1` for `n < 3`, otherwise `f(n-1) + f(n-2) + f(n-3)`;
- `split`: `f(n) = 1` for `n ≤ 1`, otherwise `f(n/2) + f(n/3) + f(n/4)` (division rounded down);
- `hof`: `f(n) = 1` for `n ≤ 2`, otherwise first `a = f(n-1)`, then `b = f(n-2)`, and `f(n-a) + f(n-b)`.
The calls on the right are made strictly left to right, and the sum is taken modulo `1 000 000 007`.

Every call of `f`, including the very first one and the base cases, goes through a cache of `capacity` values with least-recently-used (LRU) eviction. If `n` is in the cache, the result comes from there and the entry becomes the most recent. Otherwise the body is evaluated (an "evaluation"), then the result goes into the cache as the most recent entry, and if there are now more than `capacity` entries the oldest is removed. With `capacity = 0` the cache stores nothing. The cache is shared by all queries.

For each `n` in `queries` in turn return `[f(n), evaluations]`, where "evaluations" is how many times the body was evaluated during that query. Up to 20 queries, `0 ≤ capacity ≤ 100`, `n ≤ 10⁶`, recursion depth at most 200, and at most 200,000 evaluations over all queries.

Example: `"fib"`, `3`, `[10, 12]` → `[[55, 11], [144, 2]]`.
