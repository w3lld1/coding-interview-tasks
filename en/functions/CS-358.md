# Memoising Collatz path lengths

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Hash maps and sets](../hashing/), [Recursion and backtracking](../recursion/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-358?utm_source=github&utm_medium=tasks-repo)**

The function `steps(n)` returns how many steps it takes `n` to reach `1`: `steps(1) = 0`, otherwise `steps(n) = 1 + steps(next)`, where `next = n / 2` for even `n` and `3n + 1` for odd `n`.

The function is memoised with one shared cache "number → result", empty at the start and shared by all queries. Every call to `steps` — the top one and the recursive ones — first looks in the cache: if the value is there it is a hit; otherwise it is a miss: the function computes the result (recursing) and stores it in the cache, `n = 1` included.

You get a list of queries `queries` (numbers from 1 to 1000). Process them in order and for each return the list `[steps(q), misses, hits]`, where misses and hits are counted for that query only.

Example: `[2, 4, 4]` → `[[1, 2, 0], [2, 1, 1], [2, 0, 1]]`. For `2`, misses are `2` and `1`; for the first `4`, a miss at `4` and a hit at `2`; the second `4` is one hit.
