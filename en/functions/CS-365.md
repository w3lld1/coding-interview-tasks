# Typed pipeline of steps

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Errors and exceptions](../errors/), [Parsing and validation](../parsing/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-365?utm_source=github&utm_medium=tasks-repo)**

A value has a type: at first it is the string `value` (type `string`). The steps in the list `steps` are applied one after another; each takes a value of a certain type and returns a value of a certain type:
- `to_int`: string → int (decimal with an optional minus, e.g. `"-15"`; at most 6 digits);
- `len`: string → int (length); `upper`, `reverse`, `trim` (strip spaces at both ends): string → string;
- `double`, `inc`, `square`, `neg`: int → int (×2, +1, square, negate);
- `to_str`: int → string; `is_even`: int → bool;
- `not`: bool → bool; `show`: bool → string (`"yes"` or `"no"`).

Return the final value as a string: a string as is, a number in decimal, a boolean as `"true"` or `"false"`. An empty list of steps returns `value`.

If a step is unknown, receives a value of the wrong type, or `to_int` is applied to a string that is not a number (empty, just `-`, or with other characters), report an error: throw an exception, or return an error in Go. The error applies to the whole call: even when the bad step comes after several good ones.

Example: `"42"`, `["to_int", "double", "to_str"]` → `"84"`.
