# Service container with lifetimes

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Errors and exceptions](../errors/), [Trees and graphs](../trees-graphs/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-659?utm_source=github&utm_medium=tasks-repo)**

A dependency-injection container is described by a list `services`. Each line is `name lifetime dep1 dep2 …`: the service name, its lifetime (`singleton`, `scoped` or `transient`) and the names of the services its factory needs (maybe none). Words are separated by one space, names are distinct.

The queries `queries` run one after another; each query gets one service. To get a service the container first gets all its dependencies in the listed order, then calls the service's own factory once. The lifetime decides when the factory is called again:
- `singleton`: the instance is created once for the whole function call and reused by all queries;
- `scoped`: one instance per query: reused within a query, created again in the next query;
- `transient`: a new instance on every request.
A reused instance does not touch its dependencies.

Return for each query how many factory calls it caused. Report an error (throw an exception, or return an error in Go) if getting a service meets a name that is not in `services`; if a service is needed while it is still being built (a cycle); or if a `scoped` service is needed (even an already created one) while some `singleton` is being built. The error applies to the whole call. Services that no query reaches are not checked. Up to 10 services.

Example: `["db singleton", "repo transient db", "api scoped repo repo"]`, `["api", "api", "repo"]` → `[4, 3, 1]`.
