# Type inference for a tiny functional language

**Difficulty:** hard · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Parsing and validation](../parsing/), [Recursion and backtracking](../recursion/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-715?utm_source=github&utm_medium=tasks-repo)**

You are given a string `program`, an expression of a tiny functional language. Return its most general type, or `"error"` if the expression does not type-check.

Syntax (tokens are separated by spaces or parentheses):
- integers (`0`, `42`) have type `int`, `true` and `false` have type `bool`;
- a variable is a word of lowercase Latin letters, digits and `_` that starts with a letter;
- `fun x y -> e` is a function; `fun x y -> e` means `fun x -> fun y -> e`; the body extends as far to the right as possible;
- application `f a b` means `(f a) b`; an argument can only be a variable, a number, `true`, `false` or a parenthesised expression;
- `let x = e1 in e2` and `let rec f = e1 in e2` (the name `f` is already visible inside `e1`);
- `if c then a else b`: `c` has type `bool`, `a` and `b` have one type.

Built-in names: `add`, `sub`, `mul` : `int -> int -> int`; `eq`, `lt` : `int -> int -> bool`; `nil` : `[a]`; `cons` : `a -> [a] -> [a]`; `head` : `[a] -> a`; `tail` : `[a] -> [a]`; `isnil` : `[a] -> bool`. Your own bindings hide the built-in ones. The keywords `let rec in fun if then else true false` are never names.

Types: `int`, `bool`, a list `[t]`, a function `t1 -> t2` (the arrow is right-associative). The rules are ML's (Hindley–Milner): a `fun` parameter has one type in the whole body; a name bound by `let` (and by `let rec` in `e2`) is polymorphic: generalise the type variables that are not free in the environment; inside its own definition a `let rec` name is monomorphic. Unification does the occurs check: an infinite type is an error. A type mismatch and an unknown variable are errors too.

Print the answer like this: name the type variables `a`, `b`, `c`, … in order of first appearance from left to right; put an arrow on the left of an arrow in parentheses: `(a -> b) -> a -> b`; write ` -> ` between the parts of an arrow. The expression is syntactically valid, up to 300 characters.

Example: `"let rec map = fun f l -> if isnil l then nil else cons (f (head l)) (map f (tail l)) in map"` → `"(a -> b) -> [a] -> [b]"`.
