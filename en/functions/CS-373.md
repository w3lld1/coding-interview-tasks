# Production system: the first matching rule

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Parsing and validation](../parsing/), [Hash maps and sets](../hashing/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-373?utm_source=github&utm_medium=tasks-repo)**

You get a table of variables `facts` (name → integer) and a list of rules `rules`. A rule is written as `CONDITION -> ACTION` (the separator is exactly ` -> `, the words inside are separated by one space):
- the condition is `name operator number`, the operator is one of `>`, `>=`, `<`, `<=`, `==`, `!=`;
- the action is `name assignment number`, the assignment is `=` (store the number), `+=` (add) or `-=` (subtract).

Numbers may be negative. A variable that is not in the table reads as `0`; an assignment creates it.

Work goes in steps. At each step take the first rule, in order, whose condition is true right now and perform its action. If no rule matches, the work is over. At most 100 steps are made, then the work is cut off. Return the final table of variables (the original and the created ones).

Example: `{"x": 2, "y": 0}`, rules `["x > 0 -> x -= 1", "y > 0 -> x = -5", "x == 0 -> y += 1"]` → `{"x": -5, "y": 1}`: `x` drops to 0, then `y` becomes 1, then `x` becomes -5, and no rule matches.
