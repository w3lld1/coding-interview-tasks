# A tiny rule engine that infers tags

**Difficulty:** medium · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Parsing and validation](../parsing/), [Hash maps and sets](../hashing/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-363?utm_source=github&utm_medium=tasks-repo)**

You get a set of facts `facts` (name → integer) and a list of rules `rules`. A rule is written as `CONDITION => tag` (the separator is exactly ` => `). A condition is one or more simple conditions joined by ` and `. A simple condition is either three words `name operator number` (the operator is one of `>`, `>=`, `<`, `<=`, `==`, `!=`; the number may be negative) or one word, a tag name, which is true when that tag has already been derived. A condition about a fact missing from `facts` is false.

Inference works like this. Walk the rules in order; a rule that has not fired yet and whose conditions are all true right now (counting the tags already derived) fires: its tag is appended to the result if it is not there yet. A rule fires at most once. A new pass starts if something fired in the previous one; when a pass changes nothing, inference is over.

Return the derived tags in the order they were added.

Example: facts `{"age": 20, "score": 70}`, rules `["adult and score > 60 => admit", "age >= 18 => adult"]` → `["adult", "admit"]`: in the first pass the first rule is not yet true and the second fires; in the second pass the first fires.
