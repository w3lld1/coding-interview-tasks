# Work done by a memoised Fibonacci

**Difficulty:** easy · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Recursion and backtracking](../recursion/), [Hash maps and sets](../hashing/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-340?utm_source=github&utm_medium=tasks-repo)**

A function `fib(n)` with a cache works like this. If the cache already holds `n`, it returns at once and counts nothing. Otherwise it stores `n` in the cache, counts "one computation" and, when `n >= 2`, also calls `fib(n - 1)` and then `fib(n - 2)` (for `n` equal to 0 or 1 there are no other calls). The work of a call is the number of computations performed in the whole chain of calls it started.

The cache is shared by all calls from the list `calls` and starts empty. Call `fib` for the numbers in `calls` in order and return the list of the work of each call. You do not have to compute Fibonacci values. Every `n` is from 0 to 30.

Example: `[5, 5, 3, 6]` → `[6, 0, 0, 1]`. The first call computes 0, 1, 2, 3, 4 and 5, the second and third take everything from the cache, and `fib(6)` computes only 6 itself.
