# Lazy streams with a call counter

**Difficulty:** hard · **Languages:** any of Python, JavaScript, TypeScript, Java, Go · **Topics:** [Functions and closures](../functions/), [Recursion and backtracking](../recursion/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-662?utm_source=github&utm_medium=tasks-repo)**

Streams are given by a list of definitions `definitions`, each made of words `NAME = KIND ARG…`; arguments name only streams defined earlier. Kinds:
- `range A B`: the numbers `A, A+1, …, B-1` (empty if `A ≥ B`);
- `map F S`: `F(x)` for every `x` of `S`; `F` is `double` (2x), `square` (x²), `inc` (x+1), `neg` (−x), `half` (x/2 rounded down);
- `filter P S`: the elements of `S` for which `P(x)` is true; `P` is `even`, `odd`, `positive` (x > 0), `mult3` (divisible by 3);
- `takewhile P S`: elements of `S` while `P(x)` is true; the first element where `P` is false has been taken from `S` but is not emitted, and the stream ends;
- `take K S`: the first `K` elements; after emitting the `K`-th it asks `S` for nothing more;
- `drop K S`: skips the first `K` elements of `S` and emits the rest;
- `zip G S T`: `G(x, y)` for elements with the same index; `G` is `add`, `sub` (x − y), `mul`, `max`, `min`. It asks `S` for an element first, then `T`; it ends as soon as either ends (if `S` ended, `T` is not asked).

Streams are lazy: a stage asks its source for the next element only when it is itself asked for one. Every mention of a stream name is its own independent pass from the start (in `zip add i i` stream `i` is traversed twice).

For each name in `queries` traverse the stream to its end and return a list: first the number of calls of `F`, `P` and `G` functions during that pass, then all emitted numbers. Up to 20 definitions; all emitted and intermediate numbers fit in a 32-bit integer; each query emits at most 100 numbers and makes at most 10,000 calls.

Example: `["a = range 0 4", "b = map double a", "c = zip add a b"]`, `["c"]` → `[[8, 0, 3, 6, 9]]`.
