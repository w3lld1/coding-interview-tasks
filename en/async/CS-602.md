# Shared retry budget

**Difficulty:** medium · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Errors and exceptions](../errors/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-602?utm_source=github&utm_medium=tasks-repo)**

You are given a list of jobs `jobs`, a shared retry budget `budget ≥ 0` and a per-job retry limit `per_job ≥ 0`. A job is an async function with no arguments: call it (`await job()`) to run it; it may fail (throw).

The jobs run strictly one at a time, in list order: the next one starts when the previous one has finally ended. If a job fails, it may be called again at once (a retry), but only if fewer than `per_job` retries have been used for this job and fewer than `budget` in the whole list. Each retry spends one unit of the budget. If a retry is not allowed, the job counts as failed: it adds nothing and the function moves on to the next job.

Return a list of three numbers: the sum of the values of the successful jobs, the number of retries used, and the time in milliseconds from the call of the function to the end of the work. The current time in milliseconds: `Date.now()` in JS/TS, `round(asyncio.get_running_loop().time() * 1000)` in Python. For an empty list return `[0, 0, 0]`. Up to 50 jobs.

Example: jobs (10 ms, value `1`, the first attempt fails), (5 ms, value `2`) and (8 ms, value `3`, the first two attempts fail), `budget = 3`, `per_job = 2` → `[6, 3, 49]` (retries: 1 for the first and 2 for the third; 10 + 10 + 5 + 8 + 8 + 8 = 49).
