# Per-key job queues

**Difficulty:** medium · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Hash maps and sets](../hashing/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-594?utm_source=github&utm_medium=tasks-repo)**

You are given a list of jobs `jobs` and a list of strings `keys` of the same length. A job is an async function with no arguments: call it (`await job()`) to run it; it may fail (throw). Job `i` belongs to key `keys[i]`.

Jobs with the same key run strictly one after another, in index order: the next one starts at the moment the previous one with that key ended (with a value or an error). Jobs with different keys run together, with no limit on their number. The first job of each key starts at once.

Return the values of the jobs that succeeded, in the order they finished; equal moments go by increasing index. For an empty list return `[]`. The current time in milliseconds: `Date.now()` in JS/TS, `round(asyncio.get_running_loop().time() * 1000)` in Python. Up to 50 jobs.

Example: jobs that take 10, 10 and 5 ms and return `1`, `2`, `3`, keys `["a", "a", "b"]` → `[3, 1, 2]` (`3` ends at 5 ms, `1` at 10 ms, `2` at 20 ms).
