# Hedged request across replicas

**Difficulty:** medium · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-219?utm_source=github&utm_medium=tasks-repo)**

Several replicas can serve the same request: `replicas[i]` is a job that serves it on replica `i` and returns a number. A job is an async function with no arguments: call it (`await job()`) to run it; it may fail (throw). Each replica may be called at most once.

Call replica 0 at moment 0. Call the next replica by index: (a) as soon as one of the called replicas fails (one new replica per failure); (b) when `hedge` ms have passed since the last call and no failure happened in that time. Any call restarts the `hedge` count; when the replicas run out there are no more calls. The first success ends the request: return `[value, time]`, where time is the moment of that answer in ms from the start; if several replicas succeed at the same moment, pick the lowest index. If every replica fails, return `[-1, moment of the last failure]`, and for an empty list `[-1, 0]`.

Every replica takes at least 1 ms. A failure is guaranteed never to happen at the same moment as another failure or as a call under rule (b), and several successes at one moment never coincide with a call under rule (b). The current time in milliseconds is `Date.now()` in JS/TS and `round(asyncio.get_running_loop().time() * 1000)` in Python. In the tests, waits run on a virtual clock and take no real time. Up to 20 replicas, `hedge` from 1 to 1000000.

Example: replicas answer `5` after 100 ms, `7` after 30 ms and `9` after 10 ms, `hedge = 40` → `[7, 70]` (replica 1 is called at 40 and answers at 70, before replica 0).
