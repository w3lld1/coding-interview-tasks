# Lazy loading of settings

**Difficulty:** easy · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Errors and exceptions](../errors/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-700?utm_source=github&utm_medium=tasks-repo)**

An app's settings are loaded by the job `load` at the first request. A job is an async function with no arguments: call it (`await job()`) to run it; it may fail (throw). Every call of `load` is a new load of the same length; its result may differ from the previous one.

Callers ask for the settings at the moments `calls` (milliseconds from the call of the function, non-decreasing; requests at the same moment go in increasing index order). A request is handled like this: if the value is already loaded, it is returned at once; otherwise, if a load is running, the request waits for its end; otherwise the request starts a new load and waits for it. A successful load keeps the value for good, and everyone who waited gets it. A failed load keeps nothing: everyone who waited for it gets `-1`, and the next request starts a load again. In the tests no request comes exactly at the end of a load.

Return for each request a pair `[value or -1, answer moment]`, moments in milliseconds from the call of the function. The current time in milliseconds: `Date.now()` in JS/TS, `round(asyncio.get_running_loop().time() * 1000)` in Python; in the tests the clock is virtual and waits take no real time. Up to 50 requests.

Example: requests at 0, 5 and 20 ms, the load takes 10 ms and returns `7` → `[[7, 10], [7, 10], [7, 20]]`.
