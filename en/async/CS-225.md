# Token bucket request limiter

**Difficulty:** medium · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Math](../math/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-225?utm_source=github&utm_medium=tasks-repo)**

Requests arrive at the moments `requests` (milliseconds after the call, a non-decreasing list), and request `i` needs `costs[i]` tokens (`1 ≤ costs[i] ≤ capacity`). Tokens sit in a bucket of capacity `capacity`, which is full at moment 0. At every moment that is a multiple of `refill` (`refill`, `2·refill`, …) one token is added; if the bucket is already full, that token is lost.

Requests are served strictly one after another in list order: a request is served at the first moment when it has arrived, every request before it has been served and the bucket holds at least `costs[i]` tokens; then `costs[i]` tokens are taken out. A request may not overtake a waiting request ahead of it, even if it would have enough tokens. Within one moment, first the token is added (if the moment is a multiple of `refill`), then the requests of that moment arrive, then everyone who has enough tokens is served in order.

Return the moment each request is served, in list order; for an empty list, `[]`. The function is async: you may model the waiting with timers, but the answer is just the list of moments. Up to 1000 requests, moments up to 10^6, `1 ≤ capacity ≤ 100`, `1 ≤ refill ≤ 10^5`; the answers may be much larger than 10^6. Stepping through every millisecond is too slow. The current time in milliseconds: `Date.now()` in JS/TS, `round(asyncio.get_running_loop().time() * 1000)` in Python.

Example: `[0, 0, 0, 5]`, `[1, 1, 1, 1]`, `capacity = 2`, `refill = 10` → `[0, 0, 10, 20]`.
