# Batched jobs with retries

**Difficulty:** medium · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Stacks, queues, linked lists](../stacks-lists/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-220?utm_source=github&utm_medium=tasks-repo)**

You are given a list of jobs `jobs`, each returning a number. A job is an async function with no arguments: call it (`await job()`) to run it; it may fail (throw).

Run the jobs in batches through a queue that first holds every job in index order. Take up to `size` jobs from the front of the queue, call them at the same time and wait until all of them finish (successfully or with an error); only then take the next batch. A job that failed but was called fewer than `attempts` times goes to the end of the queue for another try (several such jobs from one batch keep their order in the batch); each try is a new call of the job. A job that used up all `attempts` tries is not called again.

Return `[sum of the successful jobs' values, moment the last batch finished in ms from the start, number of jobs that used up all tries]`; for an empty list return `[0, 0, 0]`. The current time in milliseconds is `Date.now()` in JS/TS and `round(asyncio.get_running_loop().time() * 1000)` in Python. In the tests, waits run on a virtual clock and take no real time. Up to 30 jobs, `size` and `attempts` from 1 to 10.

Example: jobs that answer `3` after 10 ms; fail on the first call and answer `4` on the second, 20 ms each time; always fail after 5 ms; `size = 2`, `attempts = 2` → `[7, 45, 1]` (the batches take 20, 20 and 5 ms).
