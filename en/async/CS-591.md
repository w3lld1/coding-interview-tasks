# Sliding-window limiter

**Difficulty:** medium · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Math](../math/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-591?utm_source=github&utm_medium=tasks-repo)**

You are given a list of jobs `jobs` and numbers `gap ≥ 0`, `limit ≥ 1`, `window ≥ 1` (milliseconds). A job is an async function with no arguments: call it (`await job()`) to run it; it may fail (throw). Request `i` arrives `i · gap` ms after your function was called and asks to run job `i`.

The limiter accepts a request if fewer than `limit` already accepted requests have an arrival moment `s` with `t − window < s ≤ t`, where `t` is the moment of the new request. An accepted request starts its job at once, and jobs run together with no limit on their number. A rejected request is dropped: its job is never called and takes no further part. An accepted request counts in the window even if its job later fails.

Return the values of the accepted jobs that succeeded, in the order they finished; equal moments go by increasing index. For an empty list return `[]`. The current time in milliseconds: `Date.now()` in JS/TS, `round(asyncio.get_running_loop().time() * 1000)` in Python. Up to 50 jobs.

Example: `gap = 10`, `limit = 2`, `window = 25`, four jobs of 5 ms each return `1`, `2`, `3`, `4` → `[1, 2, 4]` (the request at 20 ms is rejected: the window (−5, 20] already holds two accepted requests; at 30 ms the window (5, 30] holds only the requests at 10 and 20, of which one was accepted).
