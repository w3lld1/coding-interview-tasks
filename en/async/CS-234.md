# Async LRU cache with shared fetches

**Difficulty:** hard · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Hash maps and sets](../hashing/), [Stacks, queues, linked lists](../stacks-lists/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-234?utm_source=github&utm_medium=tasks-repo)**

Requests come to an async cache: request `i` for key `keys[i]` arrives at moment `at[i]` (in ms from the call of the function; the list is not necessarily sorted). A cache entry is either a ready value of a key or its fetch still in progress; the cache should hold at most `capacity` entries of both kinds.

A request is handled like this: (1) the key has a ready entry: it is answered at once, and the entry is used; (2) the key is being fetched: the request waits for that fetch and is answered when it ends; (3) otherwise the request creates a fetch of `fetch[i]` ms: its entry is added to the cache, and the answer comes when it ends. When a fetch ends, its entry becomes ready and is used. After each added fetch entry and each ended fetch, while there are more than `capacity` entries and some of them are ready, remove the ready entry that was used longest ago. Fetch entries are never removed, so there may be more than `capacity` entries for a while; a just-ready entry is removed too when no other ready entry exists (its requests are still answered).

At one moment, the arriving requests are handled first, by increasing index, then the fetches that end, in the order they were created. Return the answer moments in request order, with the number of fetches created as the last element; for empty lists return `[0]`. The lists have the same length, up to 50 requests, `capacity` from 1 to 50, durations from 1 to 10^6, moments from 0 to 10^6. In the tests, waits run on a virtual clock and take no real time; the current time in milliseconds is `Date.now()` in JS/TS and `round(asyncio.get_running_loop().time() * 1000)` in Python.

Example: `keys = ["a", "b", "a", "c", "a", "b"]`, `at = [0, 1, 20, 21, 40, 41]`, every fetch takes 10 ms, `capacity = 2` → `[10, 11, 20, 31, 40, 51, 4]` (at 21 the fetch of `c` evicts `b`, used longer ago than `a`; at 41 the fetch of `b` evicts `c`).
