# Writer-preferring read-write lock

**Difficulty:** hard · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Stacks, queues, linked lists](../stacks-lists/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-230?utm_source=github&utm_medium=tasks-repo)**

Coroutine `i` arrives at moment `arrivals[i]` for a lock, as a reader (`kinds[i] = "r"`) or a writer (`"w"`). Once it gets the lock, it holds it for exactly `holds[i]` ms and releases it. Readers may hold the lock together; a writer holds it alone, with no readers.

The waiting coroutines stand in one shared queue in arrival order (those arriving at the same moment in increasing index order). An arriving coroutine gets the lock at once only if the queue is empty and the lock is compatible with its current holders; otherwise it joins the end of the queue. So a reader that arrives while a writer waits queues behind it (writer preference). The queue is served from its head: a writer gets the lock when there are no holders; a reader when no writer holds it, and then every reader standing right behind it up to the next writer in the queue gets in too. A coroutine that has not got the lock `timeout` ms after its arrival gives up and leaves the queue; if a writer left, the readers behind it may join the current readers at once.

Within one moment the events go in this order: first everyone whose time is up releases the lock; then those whose waiting ends at this moment give up (if they have not got the lock at this moment); then new coroutines arrive in increasing index order. After each step the queue is served as far as it can be.

Return, for each coroutine, the moment it released the lock, or `-1` if it gave up. The function is async: it is convenient to handle the events in time order and wait for each with a timer; the current time in milliseconds is `Date.now()` in JS/TS and `round(asyncio.get_running_loop().time() * 1000)` in Python. In the tests, waits run on a virtual clock and take no real time. Limits: up to 40 coroutines, arrival moments from 0 to 100000 in any order, `holds[i]` and `timeout` from 1 to 1000000. For empty lists the answer is `[]`.

Example: `arrivals = [0, 1, 2, 3]`, `kinds = ["r", "w", "r", "r"]`, `holds = [5, 5, 5, 5]`, `timeout = 3` → `[5, -1, 9, 9]` (writer 1 gives up at moment 4, and readers 2 and 3 behind it join reader 0 at once).
