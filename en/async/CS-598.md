# Lock with limited patience

**Difficulty:** medium · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Stacks, queues, linked lists](../stacks-lists/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-598?utm_source=github&utm_medium=tasks-repo)**

You are given a list of jobs `jobs`, a list `arrivals` of moments (ms after the call of your function, non-decreasing) and a list `patience` (integers of at least 1), all of one length. A job is an async function with no arguments: call it (`await job()`) to run it; it may fail (throw). Job `i` is a critical section: at moment `arrivals[i]` it wants to take a shared lock, runs while it holds it, and releases it when it ends (with a value or an error).

One job holds the lock at a time; waiting jobs get it in the order of arrival (equal moments by increasing index). If a job did not get the lock within `patience[i]` ms of its arrival, it gives up: it does not run, does not hold the lock and does not delay the others. In the tests no wait runs out at the same moment the lock is released.

Return a list of `len(jobs)` numbers: the job's value if it ran and succeeded, and `-1` if it gave up or failed. For an empty list return `[]`. Up to 50 jobs.

Example: jobs of 10 ms return `1`, `2`, `3`, arrive at 0, 0, 0, patience `[50, 5, 25]` → `[1, -1, 3]` (the second waits for the lock until 10 ms but tolerates only 5 ms; the third gets it at 10 ms).
