# Crawling pages with a limit

**Difficulty:** medium · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Trees and graphs](../trees-graphs/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-603?utm_source=github&utm_medium=tasks-repo)**

You are given a list of jobs `jobs` (page loads) and a number `limit ≥ 1`. A job is an async function with no arguments: call it (`await job()`) to run it; it may fail (throw). Job `0` is the start page and is called at once. A job that succeeds returns an integer `v ≥ 0`, the number of new pages this page found: these are the next `v` jobs not found yet, by index (the found ones always form the start of the list), and if fewer than `v` remain, all the remaining ones are taken. Found jobs go to the end of one shared queue in index order. A page that fails finds nothing. Jobs that are never found are never called.

At most `limit` jobs run at once; as soon as a place is free and the queue is not empty, the first job of the queue starts at that same moment. A job's findings join the queue at the moment it ends. In the tests no two jobs end at the same moment.

Return a list of two numbers: how many jobs succeeded and the moment (ms from the call of the function) at which the last called job ended. For an empty list return `[0, 0]`. The current time in milliseconds: `Date.now()` in JS/TS, `round(asyncio.get_running_loop().time() * 1000)` in Python. Up to 50 jobs.

Example: jobs (10 ms, `2`), (5 ms, `0`), (7 ms, `0`), `limit = 2` → `[3, 17]` (the root finds jobs 1 and 2 at 10 ms, they end at 15 and 17 ms).
