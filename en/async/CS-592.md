# Stale search responses

**Difficulty:** medium · **Languages:** Python, JavaScript, TypeScript · **Topics:** [Async and concurrency](../async/), [Arrays and lists](../arrays/)

**[▶ Solve online on CodeShare](https://code-share.online/practice/CS-592?utm_source=github&utm_medium=tasks-repo)**

You are given a list of jobs `jobs` and a list `starts` (the same length, moments in milliseconds after the call of your function, non-decreasing). A job is an async function with no arguments: call it (`await job()`) to run it; it may fail (throw). Job `i` is a search request that the user sent at moment `starts[i]`; its answer is the job's value when it ends.

An answer is shown on the screen only if it is not stale: the index of its request must be greater than the index of every answer already shown. A stale answer is dropped. Answers that failed are not shown and change nothing. Answers that arrive at the same moment are handled in increasing request index. All requests are sent at their moments and run together.

Return the values of the shown answers, in the order they were shown. For an empty list return `[]`. The current time in milliseconds: `Date.now()` in JS/TS, `round(asyncio.get_running_loop().time() * 1000)` in Python. Up to 50 jobs.

Example: jobs that take 30, 10 and 20 ms and return `1`, `2`, `3`, requests sent at 0, 5 and 10 ms → `[2, 3]` (answer `2` arrives at 15 ms, `3` at 30 ms, and answer `1` at 30 ms is already stale).
